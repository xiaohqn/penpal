# 心灵笔友功能与逻辑简述

## 1. 产品定位

心灵笔友从普通 AI 回复工具，扩展为一个“心理书信 + AI 回信 + 人工咨询师回信”的书信系统。

核心体验是：

```text
写信 -> 投递 -> 等待阅读 -> 收到回信 -> 打开信封 -> 阅读回信 -> 继续书信往返
```

用户侧强调“慢递信箱”的情绪体验，咨询师侧强调“批量处理 + AI 辅助 + 安全提示”。

## 2. 登录与角色

系统新增注册登录机制，区分两类角色：

- 用户：写信、查看历史、继续多轮书信。
- 咨询师：处理分配给自己的人工书信任务，查看自己的历史记录。

数据按账号隔离：

- 用户只能看到自己的书信。
- 咨询师只能处理分配给自己的人工书信任务。
- 咨询师上传或处理的批量任务按咨询师 ID 持久化。

## 3. 用户侧功能

用户界面围绕“慢递信箱”设计。

主要功能：

- 写新信。
- 选择 AI 回复或人工回复。
- 选择回应风格：温柔陪伴 / 理性分析 / 启发引导。
- 查看历史书信。
- 在收到回信后继续写下一封，形成多轮书信。
- 标记书信完成。

用户收到回信时，不直接展示正文，而是：

```text
收到信封 -> 点击打开回信 -> 信纸展开 -> 逐字显示
```

如果用户已经打开过某封回信，再次进入历史记录时会直接显示正文，不重复播放动画。

用户侧不会展示内部系统信息：

- 不显示“高风险 / 危机”等风险等级。
- 不显示风险触发词。
- 不显示书信摘要。
- 不显示系统 memory。

高风险来信在用户侧只用温和说法，例如：

```text
你的来信已经被优先送达。
这封信会被更谨慎地阅读和回应。
```

危机场景会提示即时支持，但不暴露内部风险标签。

## 4. 咨询师工作台

咨询师侧不再单独使用“人工书信任务页面”，而是把人工书信任务定义为工作台中的一种批量模式。

工作台目前有三种模式：

- 普通模式：手动输入单封来信。
- Excel 批量：上传 Excel 后逐条处理。
- 人工书信：载入系统分配给当前咨询师的待回复书信。

人工书信任务本质上也是 batch session。

每条人工书信任务包含：

- 用户最新来信正文。
- 用户回应偏好。
- 完整书信往返记录。
- 风险信息。
- 对应 mail thread ID，用于完成后回写用户信箱。

咨询师在人工书信模式中可以使用完整工作台能力：

- 多角色生成草稿。
- Planner。
- 润色编辑。
- 高亮批注。
- 基于批注重生成。
- 版本回退。
- 保存历史记录。

保存并完成某条人工书信后，最终回信会自动送达用户信箱。

如果只有一条待处理任务，完成后会提示：

```text
这批人工书信已全部完成，最后一封回信已送达用户信箱，没有下一封待处理。
```

后端限制同一条人工书信只会在第一次完成时回写用户信箱，避免重复发送回信。

## 5. 辅助上下文

咨询师工作台左侧分为：

- 原始来信：只显示用户真实来信。
- 辅助上下文：显示咨询师处理所需信息。

辅助上下文目前展示：

- 回应设置。
- 风险提示：仅非 NONE 风险显示。
- 完整书信往返。

当前暂不展示 memory 摘要，因为规则式摘要容易变成复述，不够可靠。

后台仍保留 memory，用于模型上下文和后续升级。

## 6. Memory 设计

系统新增基础 memory 模块，用于多轮书信。

Memory 目标：

- 不把所有历史原文都塞进模型 prompt。
- 用摘要保存长期上下文。
- 为后续风险趋势、咨询脉络、回应连续性做准备。

当前 memory 仍是基础规则式摘要，不在用户侧展示，也暂不在咨询师侧展示。

后续可升级为结构化 memory：

```text
主要困扰
反复主题
用户表达方式
已尝试应对
需要延续的回应
风险变化
```

## 7. 安全逻辑

系统新增 Safety Engine，用于风险识别和回复安全审核。

风险等级：

```text
NONE / LOW / MEDIUM / HIGH / CRISIS
```

主要流程：

```text
用户来信
-> 风险检测
-> 写入风险记录
-> 决定 AI 回复或转人工
-> AI/咨询师回信安全审核
-> 发送
```

高风险及危机场景会优先转人工处理。

咨询师侧会看到风险等级和触发因素。

用户侧不会看到内部风险标签，只看到温和的支持性文案。

## 8. 数据与持久化

新增或扩展的核心数据：

- mail_threads：多轮书信线程。
- mail_messages：用户来信、AI 回信、咨询师回信。
- conversation_memories：线程 memory。
- risk_assessments：风险检测记录。
- batch_sessions：批量任务。
- batch_session_items：批量任务条目，支持 mail_thread_id 和 context_json。

人工书信任务通过 `mail_thread_id` 与用户书信线程关联。

咨询师完成任务后，系统根据该 ID 将回信写回对应用户信箱。

## 9. 当前重要交互约定

- 用户侧不展示系统内部判断。
- 咨询师侧展示风险，但不展示不成熟 memory。
- 人工书信作为批量模式处理，不再独立成页面。
- 打开过的回信再次进入历史时直接显示正文。
- 完成后的人工回信不会重复写入用户信箱。
- Excel 批量和人工书信批量相互区分，避免切换后显示错任务。
